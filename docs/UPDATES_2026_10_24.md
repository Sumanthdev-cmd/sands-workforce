# Source updates through 24 October 2026

This commit integrates the update packages prepared since the original public
source snapshot. It is not a new capture of the running production server, and
pushing it does not deploy the website or rebuild the Android APK.

## Included changes

- Live-map filtering, vendor locations and workforce settlement/archive workflow.
- Payroll eligibility excluding zero salary/allowance structures.
- Cashier role and credit/debit records with supporting documents.
- Date-column attendance grid, joining-date checks, employee numbering and geofence alerts.
- Downloadable financial approval records.
- Dashboard-first alphabetical navigation and readable location status.
- Manual employee codes, save-time numbering and guarded retired-code reuse.
- Archived-person attendance filtering and deletion of read notifications.
- Department creation, role-based designation choices and dashboard employee counts.
- DD/MM/YYYY display and date input controls.
- Frozen advance balances in newly finalized payroll, for employees and vendors.
- Landscape payroll register and individual payslips with navy headers, shaded
  rows, bank details and two-column salary/advance breakdowns.

## Database setup

Incremental installers originally applied SQL outside Alembic. Their exact schema
additions are preserved in backend/scripts/update_schemas, in numbered order.
For a new development database, apply the existing Alembic chain and mobile schema
setup first, then these SQL files before starting the updated application.
Use a PostgreSQL transaction per file and stop on errors. Back up any existing
database before applying schema changes. No business data or credentials are
included in these scripts.

Financial PDF export requires reportlab==4.4.9, now included in requirements.
The bundled font license is in backend/app/services/financial_export_font_LICENSE.txt
and also applies to the DejaVu fonts embedded in the payroll print stylesheet.

## Historical payroll

New finalizations capture advance totals in calculation_details. Reports for older
finalized payroll explicitly state that the historical advance balance was not
captured. They never substitute a current balance for an old payroll snapshot.
Salary arithmetic and the single advance deduction remain unchanged.
